# 固件改动说明

原版固件来自 Enactic 的 `openarm_ker_firmware`（Apache 2.0），所有文件的版权头与许可证原样保留。

## 背景：为什么要改

原版协议是**接力应答制**：M5 发广播（ID=0, CMD=2）只触发 ID1，ID1 应答后，ID2 听到 ID1 的应答才接力应答，依次传到链尾。这个设计跑完整链没有任何问题，但台架调试时是灾难——**单接一块板永远等不到轮到自己**，读不到任何数据，也没法判断是板坏了还是链路问题。

调试期间的解决路径：先改编码器侧（`main.cpp.test`，让单板也能出数），后来又做了 M5 主控侧的混合轮询（广播 + CMD=1 点名补询），最终设备回到"原版编码器 + 主控补询"的形态运行。本仓库收录的是编码器侧的两个修改版。

## main.cpp.test — 独立应答模式

改动集中在 `loop()` 的应答逻辑：

1. **广播独立应答**：收到广播（CMD=2/3）时，每块板按 `ID × 60µs` 的时隙错开后**各自独立应答**（时隙宽度约等于 4 字节包在 2M 波特率下的发送时间，不会碰撞），不再等待前驱板的包。总线上挂任意一块板、任意子集，都能直接出数
2. **CMD=1 直接点名保留**：原版的单板点名应答路径不变，可配合上位机单独查询
3. **LED 语义改为链路指示**：原版 LED 只在发送瞬间闪一下（人眼不可见）；改为收到任何总线包后亮 400 ms——M5 每 1 ms 轮询一次，链路通则常亮，断线 400 ms 后熄灭，一眼判断链路状态
4. 其余逻辑（SSC 读取、4 字节打包、20ms 兜底刷新）与原版一致

> 历史：更早还有一个 `main.cpp.diag`（9 月 3 日），只做了上述第 3 条 LED 改动，后被 test 版包含，未收录。

## main.cpp.benchdiag — 台架诊断固件

与原协议无关的**独立诊断固件**，专门用来回答一个问题：板子不出数，到底是 MCU 坏、RS485 收发器坏，还是编码器芯片坏？

特点：**115200 波特率**（普通 CP210x USB-RS485 小尾巴即可，不要求 2M）+ **单字节 ASCII 命令** + 半双工应答。

| 命令 | 应答 | 用途 |
|---|---|---|
| `L` | `OK <millis>` | 链路回环：MCU + RS485 收发器双向都通 |
| `I` | `BENCHDIAG v2 id=<id>` | 固件身份 / 板子 ID |
| `P` | `PIN CS=H CLK=L DATA=H` | 空闲引脚电平（查 DATA 线卡死/上拉状态） |
| `A` | `A 0x<raw15> <centideg>` | 单次角度读取（AVAL 寄存器） |
| `T` | `T 0x<stat> 0x<aval>` | TLE5012B 的 STAT + AVAL 寄存器（STAT 可看芯片级故障位） |
| `S` | 每 100 ms 流式输出角度，10 s 自动停 | 期间转动磁铁看读数变化 |
| `K` / `C` / `D` | CLK / CS / DATA 输出 0.5 Hz 方波 20 s | 万用表探针量引脚：跟方波走 → MCU 驱动与焊点 OK；不动 → 引脚死或走线断 |

- 任何其他字节：停止流式输出或方波测试
- LED：每收到一个字节亮 100 ms（可见的链路指示）
- 回复前有 200 µs 收发切换延时，兼容 USB-RS485 小尾巴的 TX→RX 换向时间

排障流程建议：`L` 通 → `I` 确认 ID → `P` 看引脚 → `A`/`T` 读传感器 → 还不行就 `K`/`C`/`D` 上万用表。

## platformio.ini 烧录说明

- `build_flags = -DDEVICE_ID=16`：烧哪块板就改成哪个 ID（1–16）
- `upload_port = COM8`：按本机实际串口改
- `upload_protocol = serialupdi`，57600 波特率
- 熔丝位已在配置中写死（20 MHz 内部振荡器等），PlatformIO 烧录时自动配置，无需 Arduino IDE 手动烧熔丝
